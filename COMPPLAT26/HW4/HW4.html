1. AWS vs Google Cloud vs Azure

A. What services can you use for free?

Amazon Web Services (AWS) - AWS Free Tier includes a mix of “always free” services plus a free plan with credits for new accounts. ￼

Google Cloud (GCP) - Google Cloud offers selected products free within monthly Free Tier limits, plus product-specific trials. ￼

Microsoft Azure (Azure) - Azure provides two types of free services: some free for the first 12 months and many always-free up to monthly limits. ￼

What to say academically: • Object storage is usually “cheap per GB” but you pay for operations (requests), retrieval (for cooler tiers), and especially data transfer out.

D. Compare prices and expected performance of different VM offerings. Is price linear with performance?

Within the same family and generation, price is often close to linear when you scale vCPU and RAM proportionally: • 2 vCPU/8 GB to 4 vCPU/16 GB roughly doubles price across AWS, Azure, and GCP in the examples above. ￼

But it’s not perfectly linear in practice. Common non-linear effects you can discuss: 1. Burstable vs non-burstable instances Burstable VMs can be cheaper but throttle under sustained load, so “expected performance” is not proportional to price. 2. CPU generation and platform differences Newer CPU families can deliver better perf per dollar (same price point, better throughput), and some clouds price aggressively in specific families. 3. Network and disk caps scale in steps Bandwidth, IOPS limits, and “up to X Gbps” often jump at certain sizes, so performance can increase more than linearly for workloads that are network/disk bound. 4. Discount models change the curve Commitments (1-year/3-year) and sustained-use discounts change effective pricing and can make larger steady workloads much cheaper per unit compute. ￼

E. Which of the three is best?

A defensible “no single best” answer (typical in coursework): • AWS tends to win on breadth of services, ecosystem maturity, and “there’s a service for that” coverage. • Azure is often best if your company is deeply invested in Microsoft enterprise stack (AD, Windows, MS security/governance) and wants tight integration. • GCP is often strongest for data analytics and ML-heavy teams, and has very competitive VM + discount mechanics for steady usage (plus strong Kubernetes heritage).

⸻

F. If your company wants to start using cloud, which would you pick and why?

A solid default choice (easy to justify): • Pick AWS if you want the widest service catalog, the biggest hiring pool, and lots of reference architectures. • Pick Azure if you’re Microsoft-heavy (identity, security policies, Windows workloads, M365 integration). • Pick GCP if your early roadmap is dominated by data/ML pipelines and you want tight integration with Google’s data tooling.

If you must pick one in an assignment: AWS is often easiest to defend as the “general default” for a new adopter because of maturity and breadth - then add a note that the best choice depends on workload and existing enterprise constraints.

  1. Would cloud computing have taken off like this without virtualization?

Probably not at anything like today’s scale.

Why: • Virtualization (VMs, and later containers) makes multi-tenancy safe enough (isolation), enables elastic provisioning (spin up/down quickly), and allows efficient resource pooling (high utilization). • Without it, cloud would look more like “hosted dedicated servers” - slower to provision, harder to automate, and more expensive because providers couldn’t multiplex workloads effectively.

3-5) Armbrust et al. (2010) - classify the 10 points today

The paper’s 10 “obstacles/opportunities” are listed in their table of predictions. ￼ I’ll classify each as mostly true, partially true, or mostly untrue in today’s cloud.

Points 1-3

  1. Availability / Business Continuity - Partially true Cloud availability improved massively (multi-zone, multi-region, managed failover), but major outages still happen and customers still need resilience design.

  2. Data Lock-in - Mostly true Containers, Kubernetes, Terraform, and open APIs reduce lock-in for basic compute, but managed services (databases, event systems, IAM, observability) still create strong lock-in - and data egress costs reinforce it.

  3. Data Confidentiality and Auditability - Partially true Security tooling is far better (encryption, KMS/HSM, IAM, logging, compliance), yet confidentiality and auditability remain central concerns, especially for regulated industries and sensitive data.

Points 4-6

  1. Data Transfer Bottlenecks - Partially true Networks are faster, and physical transfer appliances exist, but large dataset movement, cross-region replication, and egress remain bottlenecks (cost and latency).

  2. Performance Unpredictability - Partially true Better instance isolation options exist (dedicated hosts, premium SKUs), but shared infrastructure and noisy-neighbor effects haven’t disappeared, especially for storage and multi-tenant services.

  3. Scalable Storage - Mostly true This is one area where cloud clearly delivered: object storage and managed storage systems scale elastically and are operationally simpler than most on-prem alternatives.

Points 7-10

  1. Bugs in Large Distributed Systems - Mostly true Still a fundamental issue. Systems are bigger and more complex; the industry improved practices (SRE, chaos engineering), but distributed failure modes remain hard.

  2. Scaling Quickly - Mostly true Elasticity is real, and automation is strong (autoscaling, IaC), but organizational bottlenecks (quotas, architecture, cost controls, governance) often limit “instant scaling” in real companies.

  3. Reputation Fate Sharing - Partially true Clouds are better isolated than before, but shared dependencies still bite (shared identity providers, common SaaS outages, shared IP reputation, misconfigurations).

  4. Software Licensing - Partially true A lot moved to subscription and consumption pricing, but licensing is still messy (BYOL rules, core-based licensing, marketplace images, audit risk).

If your instructor expects tighter alignment to the paper’s framing, you can explicitly say: the “obstacle exists, but mitigation mechanisms matured” for most points - and mark the ones that are essentially solved (scalable storage is the clearest).
